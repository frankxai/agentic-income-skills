# Build Agentic Funnel

Start with the existing product/catalog record and release state. Audit current pages and connectors. Choose one acquisition source, buyer action, and activation event. Reuse the current site and delivery stack until a verified limitation justifies another platform.

Read [the method map](references/contract.md) to adapt Brunson's publicly documented methods. Treat them as hypotheses rather than universal conversion laws. Create original copy and artifacts; do not reproduce chapters, paid worksheets or proprietary scripts.

Bind each promise to an artifact and evidence. Choose a diagnostic for uncertain fit, a working demo for software, a sample/reproducible excerpt for research, a workshop for a teachable process, or direct checkout for an understood product. Avoid unnecessary steps.

Build the requested funnel map, page specs, copy, proof references, consent-aware nurture drafts, checkout/delivery handoff, events and experiment. The next offer should solve the next demonstrated need. Optional add-ons must leave the base product independently useful. Remove fabricated urgency, testimonials, monetary anchors and guaranteed earnings.

Separate proposed, reviewed, checkout-tested and commercially available. Missing checkout means an honest preview, waitlist or free artifact. A model-created approval field does not authorize sales. Resolve publication authority from the session and repository.

Discover actual GitHub, Vercel, design, database and email operations and tenant permissions. A ChatGPT connection is not a SaaS backend credential. Draft external messages locally unless sending is explicitly authorized.

When connected, compile_funnel_blueprint and review_launch_readiness provide draft journeys and advisory checks. Verify underlying evidence separately. Without the MCP, perform the same reasoning directly and identify manual checks. Finish with reviewable artifacts, fulfillment path, activation metric and exact remaining blockers.
